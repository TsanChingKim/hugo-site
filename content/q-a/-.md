# C++ 中的类型转换
## 1.C 语言中的类型转换
### c 语言中类型转换的执行顺序
如果`T(x)`只执行一种转换，那么很多在C中合法的代码在C++中就会报错，为了解决这个问题，C++标准规定：
`(T)x`等价于按优先级顺序尝试：
1. `static_const<T>(x)`
2. `static_cast<T>(x)`
3. `static_cast<const_cast<T>(x)>`（先移除const，再静态转换）
4. `reinterpret_cast<T>(x)`
5. `reinterpret_cast<const_cast<T>(x)>`
### 举例
```c++
int* ptr = new int(42);
int addr = (int)ptr;
```
编译器内部发生了什么：
1. 尝试`const_cast<int*>(ptr)`：
	- 失败：因为`ptr`是`int*`，目标也是`int*`（如果目标是`int`则跳过此步？不，这里目标是`int`，所以`const_cast`尝试将`int*`转为`int*`并移除`const`，但这不改变类型，所以无效）
  - 修正：`const_cast`只能改变cv-qualifiers，不能改变基本类型，所以如果`T`和`x`类型不同，`const_cast`直接失败。
2. 尝试`static_cast<int>(ptr)：
  - 失败：C++标准规定，`static_cast`不允许将指针直接转换为整数（除非是`void*`到`uintptr_t`等待特定情况，且通常也不推荐）。
  - 所以`static_cast<int>(ptr)`是编译错误。
3. 尝试`reinterptret_cast<int>(ptr)`：
	- 成功！`reinterpret_cast`允许将指针重新解释为证书。
  - 因此，`(int)ptr`是”静态转换“，但实际上它执行的是”重解释转换“，如果你后来修改了代码，使得`static_cast`变得合法，`(int)ptr`的行为可能会突然改变！
在这个例子中，是将指针转化为int，但是一般如果是初学者可能会使用`static_cast`，但是`static_cast`并不能将指针转换为`int`，**其原因就是在内存中，`int`类型和`int*`类型的存储形态不一致。**这是这个`static_cast`报错的核心原因，其次`static_cast`并不能移除const，这是次要原因。
### 更危险的例子
```c++
const int c =10;
// 希望将 const int 转换为 int
int i = (int)c;
```
编译内部发生了什么？
尝试`const_cast<int>(c)`：
- 成功！`const_cast·可以移除`const`属性。
- 因此，`(int)c`实际上执行的是`const_cast<int>(c)`。
  
## C++ 类型转换
上面的例子如果换成`static_cast`：
```c++
int 12 = static_cast<int>(c);	// 编译错误
```
- `static_cast`不允许删除`cosnt`。

`(int)c`和`static_cast<int>(c)`的行为完全不同！
- `(int)c`会移除`const`。
- `static_cast<int>(c)`会报错。
### 为什么 C++ 要这样设计
#### 1.历史原因：C 语言的灵活性
在 C 语言中，`(int)ptr`是合法的，并且执行的是指针到证书的转换。C++为了兼容 C 代码，必须保留这种行为。
#### 2.C++的复杂性
C++ 引入了`const`、继承、多态等概念，使得类型转换变得复杂，如果`T(x)`只执行一种转换，那么：
- 很多 C 代码会编译失败
- 开发者需要动手选择`static_cast`、`const_cast`等，增加了学习成本。
### 为什么`static_cast`更安全
`static_cast`是显式的，它只执行了一种特定的转换：
1. 语义明确：你明确告诉编译器”我要进行静态转换“
2. 编译器严格检查：
	- 如果静态转换不合法（如移除`const`、指针转整数），编译器会报错，而不是静默执行其他转换。
  - 这迫使开发者意识到潜在的问题。
```c++
const int* p = new int(10);
// c 风格转换
int i1 = (int)p;
// static_cast
int i2 = static_cast<int>(*p);	// 编译错误！static_cast 不能转换 const
```
在 C 风格转换中，你可能无意间移除了`const`，导致后续代码修改了本应只读的数据，引发未定义的行为。而`static_cast`会立即报错，让你发现这个问题。
