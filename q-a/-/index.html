C++ 中的类型转换
#

1.C 语言中的类型转换
#

c 语言中类型转换的执行顺序
#

如果T(x)只执行一种转换，那么很多在C中合法的代码在C++中就会报错，为了解决这个问题，C++标准规定： (T)x等价于按优先级顺序尝试：

  1. static_const<T>(x)
  2. static_cast<T>(x)
  3. static_cast<const_cast<T>(x)>（先移除const，再静态转换）
  4. reinterpret_cast<T>(x)
  5. reinterpret_cast<const_cast<T>(x)>

举例
#

int* ptr = new int(42);
int addr = (int)ptr;

编译器内部发生了什么：

  1. 尝试const_cast<int*>(ptr)：
    • 失败：因为ptr是int*，目标也是int*（如果目标是int则跳过此步？不，这里目标是int，所以const_cast尝试将int*转为int*并移除const，但这不改变类型，所以无效）
  • 修正：const_cast只能改变cv-qualifiers，不能改变基本类型，所以如果T和x类型不同，const_cast直接失败。
  1. 尝试`static_cast(ptr)：
  • 失败：C++标准规定，static_cast不允许将指针直接转换为整数（除非是void*到uintptr_t等待特定情况，且通常也不推荐）。
  • 所以static_cast<int>(ptr)是编译错误。
  1. 尝试reinterptret_cast<int>(ptr)：
    • 成功！reinterpret_cast允许将指针重新解释为证书。
  • 因此，(int)ptr是”静态转换“，但实际上它执行的是”重解释转换“，如果你后来修改了代码，使得static_cast变得合法，(int)ptr的行为可能会突然改变！ 在这个例子中，是将指针转化为int，但是一般如果是初学者可能会使用static_cast，但是static_cast并不能将指针转换为int，**其原因就是在内存中，int类型和int*类型的存储形态不一致。**这是这个static_cast报错的核心原因，其次static_cast并不能移除const，这是次要原因。

更危险的例子
#

const int c =10;
// 希望将 const int 转换为 int
int i = (int)c;

编译内部发生了什么？ 尝试const_cast<int>(c)：

  • 成功！const_cast·可以移除const`属性。
  • 因此，(int)c实际上执行的是const_cast<int>(c)。

C++ 类型转换
#

上面的例子如果换成static_cast：

int 12 = static_cast<int>(c);	// 编译错误
  • static_cast不允许删除cosnt。

(int)c和static_cast<int>(c)的行为完全不同！

  • (int)c会移除const。
  • static_cast<int>(c)会报错。

为什么 C++ 要这样设计
#

1.历史原因：C 语言的灵活性
#

在 C 语言中，(int)ptr是合法的，并且执行的是指针到证书的转换。C++为了兼容 C 代码，必须保留这种行为。

2.C++的复杂性
#

C++ 引入了const、继承、多态等概念，使得类型转换变得复杂，如果T(x)只执行一种转换，那么：

  • 很多 C 代码会编译失败
  • 开发者需要动手选择static_cast、const_cast等，增加了学习成本。

为什么static_cast更安全
#

static_cast是显式的，它只执行了一种特定的转换：

  1. 语义明确：你明确告诉编译器”我要进行静态转换“
  2. 编译器严格检查：
    • 如果静态转换不合法（如移除const、指针转整数），编译器会报错，而不是静默执行其他转换。
  • 这迫使开发者意识到潜在的问题。
const int* p = new int(10);
// c 风格转换
int i1 = (int)p;
// static_cast
int i2 = static_cast<int>(*p);	// 编译错误！static_cast 不能转换 const

在 C 风格转换中，你可能无意间移除了const，导致后续代码修改了本应只读的数据，引发未定义的行为。而static_cast会立即报错，让你发现这个问题。
